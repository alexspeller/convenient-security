# Claude Code 2.1.311 arm64 settings-loader audit

This audit admits only cdHash `a9faecb664dd8b01e19cdfc12af95da1b267f10e`.
The existing generated-policy, marketplace/root-skill, disk-synced-skill and
remote/standalone-relay corrections remain necessary. Source tracing and the

## Identity and provenance

Anthropic's [official arm64 archive](https://github.com/anthropics/claude-code/releases/download/v2.1.311/claude-darwin-arm64.tar.gz)
matches its [published asset digest](https://github.com/anthropics/claude-code/releases/expanded_assets/v2.1.311):
SHA-256 `28dc437c4530e4fbd5e4f8924119cb001c332b64de5e817b35898c39ec107155`.
Its sole regular member, `claude`, is 276,185,504 bytes. Complete strict
signature verification, including all architectures, and the explicit
Apple-anchored Anthropic identifier/team requirement pass:
`com.anthropic.claude-code`, `Q6L2SF6YDW`, macOS arm64, hardened runtime,
signed 26 October 2026. The candidate was never executed or installed.

Table-selected extraction finds the Bun graph base at byte 93,159,432 and its
2,866-record module table at 275,196,287. It yields 2,615 UTF-8 source modules,
50,270,103 bytes. All 77,426 named static internal import/export checks pass,
with zero mapping errors.

The baseline is the exact checked [2.1.310](2.1.310.md) arm64 image,
`62f3298fb35e54f02451657e7bfbcd0b795657c7`. Its official archive digest,
strict signature and Anthropic requirement were rechecked without executing
it. Baseline extraction reproduces 2,568 modules, 49,559,468 source bytes and
75,938 valid internal references. Alpha-normalized bodies match for 56,305 of
its 58,058 function declarations; the candidate has 58,732. These matches and
dependency-name votes locate code. Constants, free bindings, imports and
callers were inspected separately; neither method proves whole-program
equivalence or certifies a version range.

The initial installed-daemon inventory has seven local rows, all checked,
with no unreadable paths and a catalog through 2.1.310. No 2.1.311 image was
discovered. Final installed catalog support and any factual image absence must
be checked again on the work bead; this audit does not update Claude to
manufacture a recovery observation.

## Newly inspected changes

The [release notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.311)
identify plugin-directory detection, synced skills and hook-dispatch changes.
They are navigation leads; the conclusions here come from the exact source.

The new `CLAUDE_CODE_EVEN_MORE_DANGEROUSLY_SKIP_PERMISSIONS` reader does not
disable auto-mode classification. Its removal-prompt waiver in `Qgn`
@229525594 requires the effective mode to be `bypassPermissions`, with no
hook ask floor or applicable PermissionRequest hook. `M6r` @222989642 in
`chunk-tgxqfh32.js` also requires settled, readable, clear sources and refuses
child sessions. G6 already refuses reachable bypass. The new key is excluded
from settings-applied env and scrubbed from tool-child env. Its pure-auto
presence is included in the exact-image csec fixtures.

The new empty-classic-dispatch shortcut `Efn` @224937065 in
`chunk-agd6r8pb.js` recognizes only the sealed default module. The actual
PreToolUse path `pvr` @229932292 still checks `Eye` @229998016 before
returning early. `Gre` @229996673 distinguishes real settings hooks, no hooks
and unknown source state; both real and unknown states keep that path active.
The `command.describe`/`env.get` shortcut does not create an earlier shell
approval path. Probes check these decisions as well as main/REPL ordering.

Plugin-directory detection `upo` @227293609 now ignores a zero-byte regular
`.mcp.json` when recognizing a folder of plugins. A nonempty or unreadable
marker remains blocking evidence. This operates behind the independently
refused explicit plugin launch selectors. Registry and ordinary plugin roots
remain the gate's existing sources.

Changed synced-skill construction still carries the original hook object.
Its allowed-tool getter can withhold grants without stripping those hooks.
The sync list's reuse/refresh still materializes through the account bucket
and existing synced roots, then the ordinary disk parser and hook registry;
it is not the memory factory that erases capabilities. No account/login data
was read to choose a bucket.

Model-catalog source selection `Q7e` @235838165 retains compiled verification
roots even for an environment-selected URL. Its managed source reader `m`
@235837300 returns undefined URL/key fields in this image. Unsupported and
loopback URLs are refused. The separate source verifier still requires a
signature; the fixtures never substitute URL provenance for that check.
Existing non-first-party classifier transport refusals remain required.

The MCP server handler moved again: actual `W` @260651573 is in
`chunk-vj7qa45r.js`, rather than the module holding most old MCP CLI handlers.
Its imported `P1e` still returns false, so HTTP-only launch plugins/settings
and workspace roots remain dormant. The sealed Claude Test middleware still
passes through the next decision/error and adds no shell approval hook.

The environment comparison includes wrapped `i` readers as well as direct
`process.env` reads and registry identifiers. The native images also expose
the same 204 `BUN_`, `NODE_`, `DYLD_` and `JSC_` identifiers, with no added or
removed name; that comparison does not prove native runtime equivalence.
`AUTO_MODE_MODEL` retains its
existing policy; `BG_CLASSIFIER_MODEL`, `TWO_STAGE_CLASSIFIER`,
`AUTO_MODE_EXTERNAL_PERMISSIONS` and `ENABLE_AUTO_MODE` still have no
behavioral reader under their full `CLAUDE_CODE_` names. The other new readers
concern telemetry, output, MCP listing, hook-event notifications, narrower
proxy trust-store work, or background/runner scheduling. The incremental-body
serializer changes request representation, not the classifier's selected
body authority. No additional approving source or transport selector was
found.

## Probes, regressions and limits

Thirty-five offline probes execute selected actual declarations/expressions
with synthetic dependencies. They cover the full prior 30-case source set
plus the removal waiver, empty MCP marker, changed synced constructor,
model-catalog source trust and the empty-classic shortcut. They never import
an upstream module or run the candidate binary. Real model verdict quality,
native/server behavior and whole-program or cryptographic correctness are
outside this fixture claim. Schema, account, crypto and transport answers
inside the fixtures are synthetic.

Tools, reviewed mappings and final/initial logs are attachment `010220b7473a`
on the work bead. Alpha-renaming preserves local shadowing, and the final
selector refuses missing explicit mappings rather than reusing a minified
name that could now identify unrelated code. Intermediate probe failures
were minifier/local-name/module movement or incomplete synthetic dependencies;
the MCP marker's expected failure disposition was corrected against source.
No gate defect was inferred from fixture drift. No live settings, login,
credential, session token or proxy was used.

Csec regressions check exact and neighboring hashes across secret access,
SSH and sudo, including renamed executables and the inspected environment
selectors. Compatibility-isolated controls preserve hosted/standalone relay,
body-override, generated-policy and disk-synced-hook refusals independently of
catalog admission. The catalog and three positive service checks failed
before admission, while their neighboring-image and policy controls passed.

The work bead records actual final suites, warnings-as-errors and project
gate results, validated/pushed commits, the canonical install receipt and
installed-daemon observations. Full installation includes the sudo helper and
iPhone app. A source catalog alone is not runtime delivery or recovery.
