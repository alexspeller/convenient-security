## Corrected standalone-relay gap

The hosted relay `Wei` @247908000 in `chunk-0mavex9c.js` still requires
`CLAUDE_CODE_REMOTE`. The new standalone relay `Kei` @226017909 in
`chunk-mxenr25p.js` has a separate path. Startup `V` @230105915 in
`chunk-v6wnqwrs.js` invokes it whenever `CCR_AGENT_PROXY_RELAY_MODE` is
present. Mode `agent_proxy_standalone` requires BYOC environment metadata,
a usable session identifier/token and an HTTPS URL from
`CCR_AGENT_PROXY_STANDALONE_URL`; it does **not** require
`CLAUDE_CODE_REMOTE`. It starts a local forwarder and applies proxy variables
for subsequent traffic. Its session checks do not establish the local
runtime the delegation gate attests.

The shared G5 list now refuses `CCR_AGENT_PROXY_RELAY_MODE` on presence,
both at launch and in every inspected settings/global/inline env source.
This preserves the existing unsupported-remote-runtime boundary on secret,
SSH and sudo, using their ordinary shared review reason. The inactive URL
companion alone remains admitted. No live rule, grant, pairing, publisher
trust, provider or approval-panel implementation is edited.

A selected-source probe executes the complete initializer with synthetic
session data and a stub forwarder, without `CLAUDE_CODE_REMOTE`, and observes
`kind=on` and proxy env application. This proves that local source path;
it does not demonstrate TLS interception, classifier-response forgery or a
live exploit. No actual proxy, session token or login data was used.

## Newly active model selector

`CLAUDE_CODE_AUTO_MODE_MODEL` now has a client-side reader, as the
[release notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.302)
announce. `j3e` selects a vetted server `modelByMainModel`/`model` first,
then vetted local env, then the default. `l_e` rejects organization-disallowed
models; env choices also pass `_Mo`'s escalated-check safeguard. Both
classifier stages retain the existing prompt/request/provider chain.
Server-side permission context contains no such local env model override.

This remains admitted under the existing policy that model choice can
change verdict quality while the same Anthropic API and prompt decide.
G5 still refuses request-body/provider/transport/prose overrides. The old
statement that this particular name has no reader is corrected in the gate
comments and threat model; the other three named dormant selectors retain
their existing disposition. The probes use synthetic policy/safeguard
inputs, so they do not measure real model quality or server behavior.
