## Differences and probes

Unlike 2.1.302 and later, this image has no direct member reader for
`CLAUDE_CODE_AUTO_MODE_MODEL`, `CLAUDE_CODE_BG_CLASSIFIER_MODEL`,
`CLAUDE_CODE_TWO_STAGE_CLASSIFIER`,
`CLAUDE_CODE_AUTO_MODE_EXTERNAL_PERMISSIONS` or
`CLAUDE_CODE_ENABLE_AUTO_MODE`. Their registry declarations do not activate
them. Model selection still follows vetted server policy/defaults.
The later email/remote-browser classifier selectors are absent.

Compared with checked 2.1.305, the only candidate-only environment name is
`CLAUDE_CODE_SETTLE_TOUCHED_FILES`, used in read-file settlement; there is no
candidate-only long-option literal. Process-wrapper consumers remain Claude
self/background respawns, independently gated as new processes. The HTTP
tool-server transport remains compiled off and has no launch-plugin source.
The sealed Claude Test module registers command, skill and SubagentStop
middleware, with no shell approval hook.

Twenty-six offline probes exercise the selected actual source: trusted G1,
all-source shell filtering, roots/helper/alias/rename behavior, v5, model
precedence, request-body ordering, main/REPL ordering, synced-hook retention
and actual registration, memory stripping, server context, prompt ablation,
signed-data refusal, both relays, sealed built-ins, host roots, builtin hook
events, HTTP reachability, root-skill fallback, unused selector readers and command-produced plugin roots.
Reproduction tools and logs are attached to the work bead, without upstream
source or executables. Initial failures were fixture/name/module drift,
resolved against actual source; the final run has 26 passes and no failures.

The probes use synthetic dependencies and binding-preserving alpha renaming
for older fixtures. They import no upstream module, run no native candidate
and read no real settings, login or credentials. They establish selected
source behavior, not whole native-runtime, cryptographic, server or real
model correctness.

csec regressions check the exact and neighboring identities on secret, SSH
and sudo, including renamed executables and the inactive selectors.
Compatibility-isolated controls retain hosted/standalone relay, body override,
generated-policy and synced-hook refusals. The work bead records failing
assertions before admission, final gates, push/install receipt and observed
installed-daemon recovery. No live classifier-rule change or repeat setup is
part of this audit.
