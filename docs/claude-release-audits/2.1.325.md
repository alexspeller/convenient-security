# Claude Code 2.1.325 arm64 settings-loader audit

Audited on `csec-cc-v2-1-325`. The catalogue admits only the exact arm64
identity below. Installation and installed-daemon recovery evidence remain on
that work bead.

This is a source delta audit from the exact audited
[2.1.319 image](2.1.318.md) straight to 2.1.325. 2.1.321, 2.1.322 and 2.1.323
were not audited and stay unchecked. The watch reported no 2.1.320 or 2.1.324.
The delta needs one settings-gate correction: the new
`CLAUDE_CODE_USER_DELEGATED_SESSION` family declines on presence (below).
The existing generated-policy, marketplace/root-skill, disk-synced-skill,
relay, provider/body override and stored Cloud-gateway guards remain required.
Publisher/custom-build trust is separate. This audit does not authorise a
Claude Code upgrade or certify other images or architectures.

provides the `claude-darwin-arm64.tar.gz` asset. Its SHA-256 matches GitHub's
asset digest. The archive's sole regular member, `claude`, was kept without
executable permissions. The candidate was never executed or installed.

## Correction: delegated-session classifier selectors

2.1.325 adds `CLAUDE_CODE_USER_DELEGATED_SESSION` with `_DIRECT_API`,
`_ALLOWED_CHECK_MODELS`, `_ANY_CHECK_MODEL` and `_ALLOWED_PROVIDERS`; none
exist in 2.1.319. In a delegated session, `j3e` returns the session's own
classifier default (`LHr`) before the server-config and organisation-policy
precedence that makes `CLAUDE_CODE_AUTO_MODE_MODEL` acceptable.
`_ALLOWED_CHECK_MODELS` replaces the list of allowed checkers.
`_ANY_CHECK_MODEL` lets the main model check its own actions. `_DIRECT_API`
changes the check's routing, MCP server policy and what happens when no
checker is available. Delegation trusts the classifier's verdict, so all
five names now decline on presence from every settings environment layer and
from inline launch settings (`ClaudeDelegationGateLists.environmentNames`).
Nothing reads `_ALLOWED_PROVIDERS` yet beyond the lists that pass the family
to child sessions. It declines with the rest so that a later reader is
already covered.

## Other material deltas

The environment inventory has 38 new names and removes none. Apart from the
family above, every new name is diagnostics, UI or timing, is covered by an
existing refusal, or only narrows:

- Desktop and host-gated names (`SHOWN_PLUGINS_DIR`, `DESKTOP_*`) need the
  entrypoint that the refused `CLAUDE_CODE_ENTRYPOINT` supplies.
- `BRIDGE_SETTINGS_BINDING` only adds an integrity check to `--settings`,
  which is itself refused.
- `BRIDGE_CHILD_START_DIR` exits on a mismatch.
- `HOST_OWNED_CONFIG_DIR` only changes recovery from an unparseable global
  config, falling back to defaults.
- `PLUGIN_MCPB_DIR` moves the MCP-bundle extraction cache. It is not a hook
  or settings source.
- `DISABLE_EXPORTED_VARIABLE_PROMPT` relaxes an extra prompt only on Bash
  allow-rule matches, which G1 removes.
- `BG_SESSION_CREDENTIAL` is a background-only account pin, not a provider
  route.

`CLAUDE_CODE_BG_CLASSIFIER_MODEL`, `CLAUDE_CODE_TWO_STAGE_CLASSIFIER` and
`CLAUDE_CODE_AUTO_MODE_EXTERNAL_PERMISSIONS` still appear only as registry
getters and in sanitization lists, with no member reader or importer, as in
2.1.319. `CLAUDE_CODE_ADOPT_UNDERIVABLE_PARKED_PERMISSION` no longer appears.
Its shared refusal stays because older catalogued images still read it.

The sealed privacy plugin was rewritten (`chunk-tvtpkkxr.js` →
`chunk-b0pqs69t.js:ne`). It now refuses a shell, web, write or MCP call that
carries the signed-in account's email beside what looks like a client
identity, or that puts the email in a fetched URL. It also reads scripts the
command names through the sealed fs, skipping links. Downstream denies and
errors still pass through untouched; the only verdict it adds is a deny. It
is still default-on, trusted-settings-only and flag-available
(`tengu_wise_newt`, default true).

The plugin-catalogue preview (`chunk-z9mf16a3.js:$e`) still only describes
hooks. A `hook_modules` entry without the module capability now yields no
preview at all, and one with it is marked `hasModule`. The repository
environment snapshot wrapper moved unchanged (`gFe` →
`chunk-612ccmj9.js:F2`). A repository still cannot switch the server check
back on over an outside off choice. The classifier rule collector
(`chunk-x4r54n7x.js:Er`) is still private, and its subset wrapper still
returns only deny lists. Sandbox defaults, write fences and the hook merger
change only names or add narrowing reasons.

Stored provider routing still restores top-level `enterpriseGateway`. Its
2.1.325 renewal path applies only to a session already on that gateway. The
Keychain, plaintext fallback and `CLAUDE_SECURESTORAGE_CONFIG_DIR` readers are
unchanged. This trace reads upstream source only, never real credential
records.

## Probes, regressions and limits

The 79 cases inherited from 2.1.319 run against 2.1.325. On name mapping
alone, 68 passed on the first run. The other 11 failed on fixture or name
drift, not behaviour: new dependency names (`A2n`, `YY`/`xn`, `IRt`, `tp`,
`HHr`, `Srn`), functions that moved (`MZn`, `F2`, `Er`), or a restructured
function. Each correction was checked against both sources. Two functions
were restructured, so their cases now run natively on 2.1.325 code and assert
the same property: the G1 allow filter (`KB/L`, now also asserting the
`bBr` command-source drop) and the privacy middleware (deny and error
passthrough, deny-only output, linked scripts unread). Delta assertions were
added for the delegated-session and host-managed-provider retirement
branches, the hook-module preview, and the additional-directory exclusion.
All 79 pass (exit 0). The cases import no upstream module, execute no
candidate runtime and use no real settings, identity, login, proxy or model.
They establish selected client-source behaviour, not whole-program, native
runtime, model quality, server behaviour or cryptographic correctness.

csec's regressions require the exact 2.1.325 identity to delegate, and the
neighbouring hash to stay unchecked, for secret, SSH and sudo. Each of the
five delegated-session names must decline from every settings environment
layer and from inline launch settings, and the protocol's name list must
match exactly. Before the fix, `--claude-delegation-only` and
`--delegation-setup-only` exited 1 on the new assertions.
`--delegation-protocol-only` also exited 1: two failures were the new
assertions, and three came from a self-test-only build that lacked the debug
`csec` binary. After the fix, all four complete affected suites exit 0:
`--claude-delegation-only` (1,376 ok), `--delegation-protocol-only` (528),
`--delegation-setup-only` (740) and `--claude-session-facts-only` (139, plus
the optional live Claude identity check, explicitly unset). The full package
build with `--jobs 2 -Xswiftc -warnings-as-errors` exits 0.
