# Claude Code 2.1.317 arm64 settings-loader audit

This audit admits only macOS arm64 cdHash
`9fd02acbf815f7259d78c4f779c2930ad33ca9aa`. The delta from the exact audited
[2.1.316 image](2.1.316.md), source tracing and 64 isolated probes establish
no additional settings-gate correction specific to this image. The existing
generated-policy, marketplace/root-skill, disk-synced-skill, relay and stored
Cloud-gateway guards remain required. Publisher/custom-build trust stays
separate. Other images and architectures remain unchecked.

Work, reproduction evidence, actual gate results, delivery and installed
acceptance belong to `csec-cc-v2-1-317`. Catalog admission does not upgrade
Claude Code; that requires the independent exact-version decision.

## Server safeguard retry

`JJe` @265102479 in `chunk-vrwkjdrd.js` adds 422 and a bounded unnamed-403
case to the existing 400 diagnostic retry. The caller resends one API request
without the dangerous-tool-use beta header and safeguards field to identify
a gateway rejecting them; it does not return an allowing tool verdict.
Named model/policy errors remain excluded, and an inconclusive rejection
does not disable the header on the next request.

The 403 branch specifically needs `LCn` @261765635 in
`chunk-rfm3fnc4.js`: a first-party provider with `ne()` false. Following `ne`
through `Ci` / `HG` / `Uu` shows that `LCn()` is false for the default
first-party URL. The branch instead requires a custom base URL, or the alternate Unix
socket case. csec independently refuses those environment selectors and
stored gateway sign-ins. Existing local classification, G1 filtering,
retired-classifier refusal and PreToolUse ordering remain required; no new
gate exception is added for a gateway error.

## Launch and environment selectors

An AST inventory records actual selector member reads separately from the
typed environment registry and string allowlists. The previously inactive
BG_CLASSIFIER_MODEL, TWO_STAGE_CLASSIFIER and AUTO_MODE_EXTERNAL_PERMISSIONS
names still have no member reader. AUTO_MODE_MODEL retains its audited
selection policy.

New or newly inventoried readers affect remote skill-watch timing, MCP-task
and subagent-handback suppression, headless exit/stream output, background
session liveness, temporary-path layout, nested transcript IDs, resume-hint
text and message-origin metadata. PERSONAL_HOOKS_OFF supplies explanatory
text in `rei`, preserving an existing stop; it does not grant a permission.
PROGRAM_USE_CASE_ID supplies the beta-gated field described above.
DISABLE_HTTPS_AGENT_KEEPING controls connection reuse and already existed
in the baseline. None supplies an additional settings/hook source or a
classifier prompt, model, provider or endpoint override.

The only added whole option-shaped string literal is `--no-create` in the
shell recogniser's `touch` flag table, not a new Claude launch option. G1
still removes the entire Bash/Monitor allow path, including this syntax.
Existing headless, SDK, host, remote, settings/inline-plugin, bypass,
disabled-hook and sandbox-auto-allow boundaries remain independent of hash
admission.

## Probes, regressions and limits

The exact baseline passes all 53 inherited probes. The candidate passes 64:
the inherited cases plus eleven cases covering the personal-hook diagnostic,
explicit callback failure blocking and its actual PreToolUse/PermissionRequest
wrapper, beta-gated use-case metadata, native credential-factory legs,
additional-marketplace source filtering, catalogue-only hook previews and
the bounded server retry/default-endpoint distinction. The all-source
filter fixture includes every current source, including `mcpMount`.

Initial failures were moved serialization code, minified locals and added
synthetic dependencies, inspected against the actual source before adapting
the fixtures. Missing mappings assert; selected declarations/initializers
run with synthetic dependencies without importing upstream modules, running
the candidate, reading real settings/login data or contacting a model/server.
This does not establish native/server behaviour, model quality,
whole-program or cryptographic correctness.

csec regressions require the exact identity on secret, SSH and sudo, keep
its neighbour unchecked and test independent source/transport declines.
Before catalog admission, the catalog assertion and all three positive
service checks fail; neighbour and boundary controls pass. Additional synced
frontmatter checks cover agent/MCP descriptors and failure-policy changes
through the existing whole-source acknowledgement.

The work bead records actual affected-suite, warning-clean build and project
gate results, source/push identity, install receipt, final doctor/phone proof
and installed-daemon inventory. Source parsing uses one 3 GiB heap; local
Swift/Xcode CI builds are capped at two jobs. Observed installed support and
factual candidate absence remain distinct from live admission of an installed
2.1.317 process.
