## Newly inspected changes

The [release notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.310)
identify broader Monitor availability. G1's actual all-source filter still
removes Monitor as well as Bash/PowerShell allow paths; provider availability
does not introduce an earlier dispatch or alternate approver.

The standalone relay now reads `SELF_HOSTED_RUNNER_AGENT_PROXY_URL` rather
than the earlier companion. Its first branch still requires
`CCR_AGENT_PROXY_RELAY_MODE == agent_proxy_standalone`; the new URL alone
returns off. Existing G5 refusal of that selector covers the new companion.
Runner-only proxy/check-out flags dispatch through `self-hosted-runner`.
`--runner-declares` carries nested-repository display metadata. New SSH/server
markers feed host/prompt context rather than an approving settings source.

Claude Test's sealed registration `ra` in `chunk-frgrmerx.js` @254800973 adds
`tool.call` observers. Each first awaits the next handler and returns its
result; the scoped wrapper propagates errors through `finally`. It adds no
PreToolUse/PermissionRequest approval registration. Native callback probes
preserve the next denial and error, rather than merely checking event names.

The HTTP MCP transport gate `I$e` in `chunk-t0kv6pst.js` still returns false.
`vs` in `chunk-92hkp1c8.js` @258727110 therefore selects stdio even when HTTP
is requested. Plugin, settings and workspace launch inputs under the HTTP
branch remain dormant in this exact image. A future enabled gate requires a
fresh audit; no version range is inferred from this result.

The remote-browser reader moved to `M`/`c3s` in `chunk-8nembzh7.js`, retaining
vetted payload provenance, formatting bounds and tool/context checks. Email
`wtt` @228091082 still selects sealed framing rules. The thread-ask-held
selector changes how existing context is compacted. These do not introduce
arbitrary local policy prose or request-body authority. The request's new
effort fallback removes refused effort/beta metadata and retries through the
same chain. The model selector introduced in 2.1.302 retains its disposition;
`BG_CLASSIFIER_MODEL`, `TWO_STAGE_CLASSIFIER`, `AUTO_MODE_EXTERNAL_PERMISSIONS`
and `ENABLE_AUTO_MODE` still have no behavioral readers under their full
`CLAUDE_CODE_` names. Other new selectors concern UI, sync, artifact/host
features or narrower policy. The probes do not assess real model verdict quality.
