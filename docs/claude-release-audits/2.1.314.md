## Changes inspected in this release

The [release notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.314)
provide leads for settings-source filtering, Monitor hooks and file-write
restrictions. Conclusions here come from the distributed source.

`Cx` now uses the selected-source accessor when collecting classifier rules;
the separate G1 accessor retains its strict trusted-layer behavior. Reading
all possible files conservatively remains valid for csec, and the existing
launch-selector refusal prevents an excluded source from being assumed active.
Managed-policy composition adjusts provider-family shadowing and region
fallbacks using existing policy/settings environment. csec already inspects
those source environment blocks conservatively. `Jh`/`Cl` preserve mandatory
refresh intent even when a stored remote policy is rejected, without admitting
that copy. No helper or live managed source was run.

Monitor calls with a command gain a Bash hook-matcher family through `Sz`.
`Bxn` supplies only the command/description input. The actual hook runner
`FPr` removes rewrites and both PreToolUse/PermissionRequest allows from
family-only matches; ask and deny survive. csec already treats both Bash and
Monitor matchers as shell-capable. Its own hook registration still precedes
the permission decision. No new approving hook source is exempted.

The fast classifier now sets aside an allow unless the response is complete
and its output has the expected exact shape. Incomplete/trailing output goes
to the no-verdict path rather than an allow. The local-classifier retirement
selector `bx` makes `IAe` return blocked/unavailable when active; it adds no
success verdict. Both changes are covered with synthetic selected-source
fixtures, without a model call. Model effort clamping and the expanded
request code retain final body-override precedence and the existing endpoint
and provider boundary.

The new write fence is enabled by strict true in any applicable settings
source and precedes file-write permission allows in every mode. Settings-file
protection and working-directory checks further narrow file-tool capability.
It does not supply a shell allow or an uninspected settings root.

The nine added prefixed identifiers were checked in raw source as well as
function summaries, including class methods and wrapped readers.
`CLAUDE_CODE_CCR_LONG_POLL` changes remote stream delivery;
`CLAUDE_CODE_DISABLE_POOLED_CONNECTION_IDLE_LIMIT` changes connection reuse;
`CLAUDE_CODE_MEMORY_CONTEXT_NO_WAIT` changes memory-context scheduling;
`CLAUDE_CODE_UPFRONT_TOOLS` affects tool disclosure; and
`CLAUDE_CODE_BRIDGE_CHILD_CLI_ENTRYPOINT` affects bridge entrypoint naming.
None grants permission or supplies a new hook/settings source.
`CLAUDE_CODE_STREAM_EVENT_HOLD_MS` and
`CLAUDE_CODE_STREAM_EVENT_MAX_LINE_BYTES` affect print-stream output, already
outside supported interactive delegation. `CLAUDE_CODE_DISABLE_RESPONSE_COMPARISON`
has registry/privacy/serialization entries without a behavioral reader.
`CLAUDE_CODE_END_` is a generated shell heredoc delimiter, not an environment
selector. The added short filename literals concern memory/imported context,
not executable hook or settings roots.

`CLAUDE_CODE_AUTO_MODE_MODEL` retains the existing quality policy under
server/org/safeguard precedence. The complete `BG_CLASSIFIER_MODEL`,
`TWO_STAGE_CLASSIFIER`, `AUTO_MODE_EXTERNAL_PERMISSIONS` and `ENABLE_AUTO_MODE`
names under `CLAUDE_CODE_` still have no behavioral reader. Both native images
have the same 207 `BUN_`, `NODE_`, `DYLD_` and `JSC_` identifier names; that
equality is navigation evidence, not native-runtime equivalence.

The actual MCP serve handler moved to `W` @263377496 in
`chunk-y24t3tf7.js`. Its imported `xje` @221467521 in
`chunk-4kjsj4a2.js` is compiled false. HTTP launch plugins/settings and
workspace-root delivery therefore remain dormant. The new HTTP spelling and
session-tunnel handling does not activate that branch. Sealed middleware,
bypass-only removal waivers and unknown/active settings-hook handling retain
their existing boundaries.

## Probes, regressions and limits

Forty-eight offline probes execute selected actual declarations, initializers
or statements with synthetic dependencies. The previous forty cases cover
the full loader/classifier/ordering checklist. Eight additional cases cover
Monitor-family input and authority limits, canonical fast-stage allows,
classifier retirement, all-source write fences, untrusted remote-policy
refresh intent, moved global path metadata and selected classifier sources.

The source selector requires explicit mappings. The MCP handler and legacy
path selector moved away from the dominant module; the builtin initializer
needed a separate binding check. Initial failures were missing mappings,
changed local names or incomplete synthetic dependencies. Each was inspected
against actual source before updating the fixture. No probe imports an
upstream module, executes the candidate, reads real settings/login data or
contacts a model, proxy or server.

Csec regressions distinguish exact and neighboring hashes on secret, SSH and
sudo paths, including renamed executables and the inspected selector tuning.
Compatibility-isolated controls preserve hosted/standalone relay, body
override, generated-policy and disk-synced-hook refusals independently of
admission. Before adding the catalog entry, the three positive service
assertions and the exact catalog lookup failed; neighboring-image and
independent policy controls passed. An unrelated notice-deduplication failure
in the initial protocol run is retained in the work bead's gate evidence.

These probes do not establish native/server behavior, model quality,
whole-program or cryptographic correctness. The work bead retains the
reproduction tools/maps, exact provenance, source trace, initial/final logs,
affected suites, warning-clean build and full project gate outcome. It also
records validated/pushed commits, canonical full install receipt,
doctor/phone verification and installed-daemon observations. Catalog admission
alone is not installation or observed recovery.
