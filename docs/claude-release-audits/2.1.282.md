## Corrected source gap: disk-backed synced account skills

`P$o` @183629583 in `chunk-x9fwahqm.js` selects
`<config>/skills/synced/<account>/` for disk-loaded account skills.
`FP` @183623567 reads each child `SKILL.md` and passes it to
`b$o` @183616497 with `loadedFrom: syncedSkills`.

That parser preserves the hooks returned by `Yre`. Its later `q_o`
@178997558 in `chunk-16v2zr31.js` sanitizes text metadata only. It does
not erase hooks. `fkt` @183617270 keeps them, and `Oe` @200203459
in `chunk-mawsqy5g.js` registers them through `je` @200169406.
The separate `Vnn` empty-capability helper belongs to other remote/memory
loaders; it does not make this disk source hook-free.

Previously, csec stopped at `<skills>/<name>/SKILL.md`. It therefore missed
the account-bucket level, and its fixture explicitly asserted that these
files were skipped. The gate now scans every bounded account bucket under
the user configuration home's `skills/synced` root. It reads no login or
active-account state and executes nothing. Hooks use existing per-source
frontmatter acknowledgement; unreadable/oversized sources and exhausted
directory/scan budgets decline. Ordinary skill folders still load one level
deep. The checked 2.1.280 source also contains the retaining parser
(`aAr` @179960638), so this correction protects existing catalog entries too.

No live classifier settings, acknowledgements, publisher trust, grants,
pairings, secret backend or dialog implementation change here. Unacknowledged
synced hooks use the existing shared ordinary-review fallback for secret,
SSH and sudo, including its phone copy. SSH's classifier-rule exemption does
not exempt an approving frontmatter hook. Existing snapshot, mid-session
discovery and transitive module-import limitations remain.

## Probes and regressions

expressions with synthetic dependencies: strict G1; all-source shell allows
for client/served calls; alias precedence; both v5 states; generated-policy
normalization; classifier body overrides; main/REPL ordering; rename bounds;

registration; the distinct empty-capability helper; and server permission
context wiring. They import no upstream module and run neither executable.

skills, multiple accounts, unchanged acknowledgement, changed hook bytes,

fixtures preserve visible hooks/rules/environment beside invalid nested
permission fields and refuse malformed classifier rules/locks. Exact-image
and neighboring-hash regressions exercise secret, SSH and sudo admission and
the approving-hook fallback. Commands, results and observed installed
