# Claude Code 2.1.315 and 2.1.316 arm64 settings-loader audit

This audit admits only cdHashes `0be2f7d3dad265d1ef590ee83623569caab5fcdd`
(2.1.315) and `e49e58a1feeb798a46fcdd8d07bcac4ee5ad1428` (2.1.316). Source
tracing and 53 isolated probes, run against each image's own source,
establish no additional csec gate correction specific to either; a
pre-existing stored Cloud-gateway sign-in gap is tracked as `csec-kpep`. The existing
generated-policy, marketplace/root-skill, disk-synced-skill and
remote/standalone-relay corrections remain required. Other images and
architectures remain unchecked; publisher/custom-build trust is separate.
Work, validation and installed acceptance belong to `csec-cc-v2-1-316`.

## Environment selectors

Fourteen prefixed identifiers are new in raw source (string literals,
member reads and class methods), none removed.
`CLAUDE_CODE_AUTO_MODE_FULL_CONTEXT` is read only on the judge-only path used
outside auto mode, where it restores the full rule context; it changes no
provider, endpoint, body, model or verdict. `CLAUDE_CODE_DISABLE_LOOPED_CROSS_CERT_DROP`
and `CLAUDE_CODE_DISABLE_SELF_NAMED_CERT_DROP` keep certificates Claude Code
would otherwise drop from a store it already trusts; the self-named switch
only affects `NODE_EXTRA_CA_CERTS`, which already declines.
`CLAUDE_CODE_DISABLE_HTTPS_AGENT_KEEPING` affects connection caching.
`CLAUDE_BG_SOCK_ADMIT_SILENT_PEERS` and `CLAUDE_BG_SILENT_PEER_TIMEOUT_MS`
tune background-session peer admission (above). `CLAUDE_CODE_SUBAGENT_EFFORT`,
`CLAUDE_CODE_DISABLE_ULTRATHINK` and `CLAUDE_CODE_SORTED_OTTER` affect effort
and tool search; `CLAUDE_CODE_CCR_ONE_PLUGIN_LOAD_PER_RELOAD`,
`CLAUDE_CODE_MCP_NO_REDIAL_AFTER_POLICY_REFUSAL` and
`CLAUDE_CODE_MCP_SKIP_UNCHANGED_RELIST` schedule existing plugin and MCP work;
`CLAUDE_CODE_DISABLE_HELD_MESSAGE_RECOGNITION` is passed to self-hosted runner
children; `CLAUDE_CODE_SESSION_BEGAN_AS_COPY` only withholds a deferred tool
call when resuming in print mode, which already declines. None grants
permission or supplies a hook or settings source.

## Stored Cloud-gateway sign-in

The delta review found a classifier route that predates this release and that
the gate does not see. At startup `IRn` @254645075 in `chunk-a8r9352h.js`
restores a stored `enterpriseGateway` sign-in from Claude Code's secure
storage, checking only its own stored TLS pin (`gatewayTrust`), allowlist
entry and expiry, and the organization's gateway settings. Once it is
restored, `Ce` @251466409 in `chunk-7pbpn6pb.js` returns `"gateway"` without
any environment variable, and the API client builder `LN` @256055653 in
`chunk-2gw942z0.js` sends every request, the auto-mode classifier's included,
to the stored gateway URL. Auto mode is offered under the gateway provider.
The same restore exists in 2.1.314. 2.1.315 adds a hidden `claude auth login
--gateway-json` (`ei` @281567132 in `chunk-ahanvcne.js`, `runGatewayJsonLogin`
in `chunk-enbfwkss.js`) that completes the sign-in without a terminal, given a
gateway URL in user settings. That changes who can complete the sign-in, not
what a stored sign-in can do.

csec declines `CLAUDE_CODE_USE_GATEWAY` and `ANTHROPIC_BASE_URL` but reads no
credential store, so a stored gateway sign-in would choose the classifier's
verdict. The gap is the same for every catalogued image that has gateway
sign-in. Keeping 2.1.315 and 2.1.316 out of the catalog would therefore not
close it, so both are admitted on the same footing as 2.1.314, and the gate
fix is tracked separately as `csec-kpep`.

`csec-kpep` closes it for every image: csecd now declines when any of
Claude Code's credential records holds an `enterpriseGateway` sign-in, or
when it cannot check them (DESIGN.md, Delegated approval, step 8). The check
reads the store, not the image, so it does not depend on which catalogued
release restores the sign-in.

## Probes, regressions and limits

Fifty-three offline probes execute selected actual declarations, initializers
or statements with synthetic dependencies, against each image's own source
tree. They pass 53/53 on 2.1.315 and on 2.1.316. The 48 inherited cases still
pass 48/48 on the 2.1.314 baseline after their fixtures were changed to derive
minified local names from each selected statement's structure instead of
naming them; every initial failure was such a name, a moved declaration or a
new synthetic dependency, inspected against the actual source before the
fixture changed. Five new cases cover per-source classifier allow lists and
the flag `"$defaults"` drop, the compiled scheduled-task rule, the refused
remote copy's helper tier, the dormant diskless setter and background PTY
input authentication.

The explicit symbol maps were built from exact normalized-body matches (83),
reviewed counterparts of changed or identical-body declarations (17) and one
initializer, with free dependencies aligned token by token. A missing mapping
fails closed. No probe imports an upstream module, executes either candidate,
reads real settings or login data, or contacts a model, proxy or server.

csec regressions distinguish each exact hash from its neighbor on secret,
SSH and sudo paths with the inspected selectors set, keep the shared
relay/body-override/generated-policy/synced-hook boundaries and an extra CA
file declining independently of admission, and pin that a refused remote
copy's helper-tier `env` declines. Before the catalog entries existed, the two
catalog checks and the six positive service checks failed while the neighbor
and boundary checks passed.

These probes do not establish native/server behavior, model quality,
whole-program or cryptographic correctness. The work bead retains the
reproduction tools and maps, exact provenance, source trace, initial and final
logs, affected suites, warning-clean build and project gate outcome, and the
validated and pushed commits, install receipt, doctor/phone verification and
installed-daemon observations. Catalog admission alone is not installation or
observed recovery.
