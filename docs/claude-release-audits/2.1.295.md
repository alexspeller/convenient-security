## Corrected relay-transport gap

`chunk-xq124y7x.js` `jUs` @220581917 requires `CLAUDE_CODE_REMOTE` and
`CCR_AGENT_PROXY_ENABLED`, then accepts a separate `AGENT_PROXY_URL`, relay
metadata and CA configuration, including the new `CCR_AGENT_PROXY_CA_CERT_B64`.
`GUs` materializes that relay's proxy/CA environment for tools. Its endpoint
is independent of `ANTHROPIC_BASE_URL`, so the launch/settings snapshot alone
does not describe this remote session's eventual tool transport. The old checked
2.1.280 has the same remote guard and supplied proxy URL in
`chunk-xqpqy3x4.js` `gAo` @198616176.

The shared G5 environment list now refuses `CLAUDE_CODE_REMOTE` on presence,
both at launch and wherever a settings/global/inline env block can apply it.
This applies the existing unsupported-remote-driver boundary to its env
selector and covers the relay companions without refusing inactive companion
names. It protects all catalogued images and retains ordinary review on
secret, SSH and sudo. This is a source-traced remote tool-transport route;
no classifier-response forgery, live proxy or end-to-end attack was demonstrated.

The four corrections from the [2.1.267 audit](2.1.267.md) remain required.
No live classifier rule, grant, pairing, provider implementation or
approval-panel implementation is edited.

## Corrected disk-synced-skill gap

`xvr` loads `<configuration home>/skills/synced/<account>` through `aO`
as `syncedSkills`. The disk loader reads each child `SKILL.md` and calls
`rcr`, whose `Ibe`/`mvr` parsing retains hooks. `qgs` sanitizes text metadata
without removing those hooks, and `bKt` preserves them. Ordinary skill
activation (`chunk-gbqxknqt.js` `Qe` @215568671) passes them to `Ve`
@215532820 for registration. There is no synced-source exclusion at that
registration point. Read-only skill preloads omit registration, but ordinary
activation can register the hooks.

The previous one-level skill scan missed these account buckets. The shared
correction from the [2.1.282 audit](2.1.282.md), landed in `0c6e7ef`, scans
every bucket under the selected user configuration home's `skills/synced`
with the existing entry limits, unreadable-source refusals and per-source
hook acknowledgement. It reads no login/account state. This correction is
required for 2.1.295 admission as well as the older checked images.

The separate `cLn` capability-erasing factory feeds memory/attached-only
loaders; it does not establish that disk-synced skills are hook-free. An
earlier revision of this report incorrectly described the existing scan as
covering synced skills. This source trace and the added probe correct that
claim; installation must include the shared scan fix.
