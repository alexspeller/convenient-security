This audit admits only cdHash `78d6b9ed85da6de5b0847587570cb3ae268a5c96`.
It requires the existing generated-policy, marketplace/root-skill,
disk-synced-skill and remote/standalone-relay corrections. No additional gate

## Newly inspected selectors and changes

The [release notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.305)
identify mounted-plugin permission changes. The source confirms they withhold
allowed-tools when host managed-only policy applies; plugin containment checks
likewise withhold capabilities. Neither creates a hook source the gate misses.

`CLAUDE_CODE_MCP_SERVE_ENABLED_PLUGINS` supplies bounded enabled-plugin names
to the HTTP MCP server's launch configuration (`chunk-z3p1rrjb.js` `c`
@263502732 and `S`). Its only invocation is in `vs` @259597164 in
`chunk-w1bb2gsm.js`, conditional on the HTTP transport. In this exact image, transport gate
`DLe` in `chunk-e3bqdrqh.js` @217351932 is compiled to return false, so
`vs` selects stdio even when HTTP is requested and never invokes that plugin
source. The HTTP path also sets up default/noninteractive policy enforcement.
The compiled false gate establishes that this selector is dormant here; a
future image enabling it needs a new source audit before catalog admission. The new plugin
MCP-skip names only suppress discovery.

`CLAUDE_CODE_AUTO_MODE_EMAIL_SENDER_TURN` and
`CLAUDE_CODE_AUTO_MODE_EMAIL_SENDER_REPLY_TURN` choose sealed email-framing
rules through `eZe` @227912965 and `Bmr` @227910579. Supplied message text
does not become policy text. The rules retain outer-frame precedence and
restrict which sender words can establish intent. The reply mode also checks
the local/remote boundary. `CLAUDE_CODE_AUTO_MODE_REMOTE_BROWSER` gates a
tool/context-checked remote-browser rule (`whn` @227965029); its reader
`rgr` @227964752 requires vetted payload provenance, bounded formatting and
the rule validator. These remain within the existing classifier tuning and
signed server-policy boundary, rather than allowing arbitrary local prose or
request-body substitution. Probe stubs do not assess verdict quality.

The model selector introduced in 2.1.302 retains its prior disposition.
`CLAUDE_CODE_BG_CLASSIFIER_MODEL`, `CLAUDE_CODE_TWO_STAGE_CLASSIFIER`,
`CLAUDE_CODE_AUTO_MODE_EXTERNAL_PERMISSIONS` and
`CLAUDE_CODE_ENABLE_AUTO_MODE` still have no behavioral source reader.
Other new selectors concern resource warnings, retry observation, metadata,
UI focus, or narrowing plugin discovery. New Node option strings occur in
child-command analysis, not a new Claude loader option.
The mounted-drive removal option suppresses an extra tool-specific warning;
it does not remove G1's classification requirement.

## Probes, regressions and limits

Twenty-eight offline selected-source probes cover trusted-layer G1, all-source
shell filtering, ordinary/diskless roots, helper payloads, aliases and renames,
v5, model precedence/safeguards, body override, main/REPL ordering, synced
hook retention and actual registration, memory capability stripping, server
context, prompt ablation, signed-data refusal, both relays, sealed built-ins,
host-only roots, root-skill containment, mounted-plugin permissions and the
new browser/email selectors, changed sealed builtin registration and the
compiled HTTP transport boundary. Reproduction tools and logs are attached to the
work bead; no upstream executable or bundled source is committed or attached.

The probes alpha-rename free dependency bindings to reuse the preceding
audit's synthetic fixtures while preserving local shadowing. Schemas,
policy/crypto answers, account context and forwarder are synthetic. They
establish selected source behavior, not whole-program/native-runtime,
cryptographic, server or real model correctness. No real config, login,
credential, proxy or session token was used. No classifier forgery is claimed.

csec regressions exercise this exact signed hash and a neighboring hash on
secret access, SSH and sudo, including a renamed executable and the inspected
classifier tuning names. Separate compatibility fixtures isolate existing
standalone/hosted relay, body-override, generated-helper and disk-synced-hook
refusals from catalog admission. A passing catalog must not hide those gates.
Existing setup fixtures continue covering the disk sources themselves.

The work bead records failing-before-admission assertions, final gates,
commit/push/install receipt, independent doctor and installed catalog/image
observations. Installing the full canonical payload includes the sudo helper
and iPhone app; an updated source tree alone does not restore delegation.
