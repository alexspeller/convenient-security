## Corrected gaps

1. **Generated policy.** `policyHelper` and `policyHelpers` can execute and
   refresh a helper, or apply nested static defaults. The helper's
   `managedSettings` accepts hooks, classifier rules and environment entries.
   `bn` @159678909, `Pn` @159689998, `jn` @159691046 and `Po` @159698382 in
   `chunk-yyyfew8j.js` feed that output to `Dq` @159413877 and `Sa` above.
   The gate now reports `generated_policy` for either key in any possible
   managed source, including a shadowed device plist. It never executes a
   helper or offers acknowledgement of its unseen output. User/project keys
   that Claude does not treat as policy remain inert.
2. **Marketplace alias.** `chunk-ysx7ez10.js` `xq` @159332130 normalizes
   `additionalMarketplaces` to `extraKnownMarketplaces`. A non-null canonical
   value wins; absence or null uses the alias. The gate now follows that
   precedence, including inline settings and add-dir enablement.
3. **Plugin root skill.** `_Te` adopts `<plugin>/SKILL.md` when there is no
   skills directory or explicit skills path. Its frontmatter can register
   hooks. The gate now inspects that file for every discovered plugin root,
   conservatively including shadowed defaults.
4. **Marketplace renames.** `hRt` resolves catalog renames before selecting
   plugin roots. `l$e` @167947032 follows up to 16 iterations; existing names
   win, and removed, cyclic, missing or overlong resolutions load no target.
   The checked baseline's `WXe` @180633048 has the same body and bound. The
   gate now resolves the same names and inspects their relative sources,
   recorded `installPath`s and versioned caches, retaining the old roots
   conservatively across snapshots. Invalid rename tables decline.

These corrections also protect the already checked 2.1.280 loader where it
shares these sources. They change no classifier configuration, grants,
pairings, secret backend or approval-dialog implementation. All three
delegation callers retain their shared ordinary-review fallback and phone
copy; SSH's classifier-rule exemption does not exempt unreadable policy.

## Probes and regression evidence

The initial synthetic setup suite reproduced 45 failures for generated
policy, the alias and root-skill fallback. After those fixes, four further
failures isolated rename target discovery and malformed rename tables.
Fixtures cover managed JSON/drop-ins, user/device plists, remote settings,
shadowed policy, alias precedence, in-place/cache/recorded rename targets,
removals/cycles/depth bounds, and ordinary unaffected settings.

Isolated probes evaluate only selected extracted functions or AST expressions
with synthetic dependencies: G1 source selection; all-source shell-allow
filtering; the filter used by permission layers; alias precedence; both v5
flag states; helper payload normalization; classifier body overrides; and
main/REPL hook ordering; and rename resolution with its 16-step boundary.
No upstream module is imported and no candidate is
executed. These probes establish the selected behavior, not server behavior
or the safety of arbitrary plugin/helper code. Required suite, build and
installed-recovery results are recorded on the work bead.
