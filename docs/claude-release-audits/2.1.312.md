## Changes inspected in this release

The [release notes](https://github.com/anthropics/claude-code/releases/tag/v2.1.312)
identify policy refresh, skill discovery and hook scheduling changes. They are
navigation leads; the conclusions here come from the exact source.

Managed-policy invalidation `zrs` @218160783 clears account/eligibility memos
and reopens a completed ineligible load cycle after sign-in. It changes when
existing managed sources are retried, without introducing a root. Signed-cache
changes in `fg` @217946147, `FJr` @217953171 and `Gns` @217952257 retain chain,
signature, type, body, account/workspace, lifetime and organisation-pin checks.
The new fixture tests principal selection with synthetic verification outcomes;
it does not test cryptography or read an account.

The skill constructor still carries the original hooks object while its
allowed-tool getter can withhold grants. Invalid command names now return an
unoffered result rather than failing the whole load. Per-directory/path skill
selection remains inside the ordinary upward/project roots; csec scans all
applicable ancestor roots. Disk-backed synced skills still use their account
bucket and parser, then `it`/`Ct` register their hooks. They do not use the
memory factory that erases capabilities.

The model-hook admission code in `chunk-r5cyd28m.js` uses 24 active and 12
overdue slots. `GB` selects only prompt/agent hooks; the `mCr` caller gives
command hooks the ordinary lane. `VM` applies the one-second minimum to a
configured nonzero timeout. These are hook-work scheduling limits, not csec
grant expiries. The selected-source fixtures check that boundary and the
compiled limits without running a model or scheduling real hooks.

Only two new prefixed environment identifiers appear in the source graph.
`CLAUDE_CODE_HOST_GUARDS_ARTIFACTS_MCP`, read by `x` @243996216 in
`chunk-1hvj078t.js`, qualifies a desktop-host artifact MCP guard. Independent
remote and managed/strict configuration refusals remain; ordinary service
discovery still checks first-party transport and organisation policy. The
separate existing evaluation-stub branch constructs a stdio MCP child.
None supplies a shell allow or settings/hook root.
`CLAUDE_CODE_REMOTE_TOOLS_HOST_IDLE_RELEASE_MINUTES`, read by `zi`
@256408034 in `chunk-x32tgnr9.js`, configures a control-only remote-tools
channel's idle release. Existing host/remote entrypoint refusals remain.
Both names also enter the child-environment serializer. The new
`--eval-artifacts-server` literal constructs a separate artifact stdio child
in `chunk-qb8m88r6.js`; it adds no classifier approval or csec registration
path. Ordinary MCP execution is not settings-loader certification.

The changed request code still places `extraBodyParams` after the classifier
model, prompt and transcript; its final extra spread is compiled empty.
Classifier prompt construction retains the full supplied system text. Main
prompt/provider fallback changes do not remove the independent provider or
body-override refusals. `AUTO_MODE_MODEL` keeps its existing quality policy;
`BG_CLASSIFIER_MODEL`, `TWO_STAGE_CLASSIFIER`, `AUTO_MODE_EXTERNAL_PERMISSIONS`
and `ENABLE_AUTO_MODE` still have no behavioral reader under their complete
`CLAUDE_CODE_` names. Wrapped readers were included in this check.

The moved MCP serve handler is `W` @260623209 in `chunk-099a18jb.js`.
Its imported `$1e` remains compiled false, so HTTP-only launch plugins/settings
and workspace roots stay dormant. The shared empty-classic shortcut keeps
actual and unknown settings hook sources active; the removal waiver remains
bypass-only. The sealed middleware preserves the next decision/error.
Raw native-image searches also find identical sets of 207 `BUN_`, `NODE_`,
`DYLD_` and `JSC_` identifiers. Identifier equality does not establish native
runtime equivalence.

## Probes, regressions and limits

Forty offline probes execute selected actual declarations or expressions with
synthetic dependencies. The previous 35-case set covers source selection,
helper output, aliases/renames/root skills, v5, shell-rule filtering, classifier
model/context/body authority, main/REPL ordering, synced parsing/registration,
memory stripping, server permissions, signed data, both relays, host and sealed
builtin roots, mounted restrictions, browser/email context, compiled-off HTTP,
sealed middleware, the removal waiver, MCP marker and empty-classic handling.
Five new cases cover managed-policy invalidation, artifact guards, the
control-only idle selector, model-hook admission and signed-cache principals.

The source selector requires an explicit reviewed mapping; moved functions and
reused minifier names cannot silently substitute unrelated code. Initial
failures were mapping, local-name or incomplete synthetic dependency drift;
they were checked against the actual source before correcting the fixtures.
They established no csec gate defect. Tools, reviewed maps, provenance, trace
metadata and probe results are retained as attachment `b07d4ae09305` on the
work bead, without the upstream executable or bulk source.

These fixtures do not establish native/server behavior, real model quality,
whole-program or cryptographic correctness. They import no upstream module
and use no live settings, login, credential, proxy or model call.

Csec regressions check exact and neighboring hashes on secret, SSH and sudo
paths, including renamed executables. Compatibility-isolated controls retain
hosted/standalone relay, body-override, generated-policy and disk-synced-hook
refusals independently of admission. Before the catalog change, exactly the
three positive service checks and the positive catalog lookup failed; the
neighboring-image and independent policy controls passed.

The work bead records the final focused suites, warnings-as-errors and project
gate results, validated/pushed commits, canonical full install receipt,
doctor/phone verification and installed-daemon observations. A source catalog
alone is not runtime delivery or recovery.
