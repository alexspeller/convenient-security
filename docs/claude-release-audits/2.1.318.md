## Material deltas

2.1.318's `chunk-tnnqa9hb.js:Ae` catalogue preview adds capability-gated HTTP
hook descriptors, including complete failure/environment metadata. It does
not execute handlers. In 2.1.319 this is `chunk-qc7bb4x5.js:Re`; the further change describes an invalid
MCP server. csec already inspects the entire handler/frontmatter block.

2.1.319's trusted classifier-rule collector is now private `no(sources)` in
`chunk-w05t2avg.js`. The public `rP()` wrapper fixes its sources to user,
flag and policy. The separate `eva(sources)` wrapper returns only deny
lists, never allow or environment entries. The shared source list and actual
callers were checked, rather than treating the new source argument as an
unrestricted public allow path.

With persisted trust ignored, `chunk-m2vza6py.js:r` uses the trusted-only
hook merger: user, flag and policy hooks remain; repository hooks are removed.
`permissions.denyInsteadOfPrompting` and refusal-run handling in
`chunk-24jdhyyr.js:Ycr/u8t` can deny and end the turn before the permission
pipeline. They cannot upgrade an ask. Genuine denies remain errors downstream.

In `chunk-nxrsh8va.js`, local-classifier retirement now accounts for disabled
telemetry/feature flags, outside-auto-mode calls and handoff review. Explicit
server-off retains local classification; the retired path still returns
blocked/unavailable without a model call. A repository cannot switch the
server check back on over an outside off choice: `Xe` reads through the
repository-environment snapshot wrapper `gFe`. Gateway/beta eligibility has
additional explicit policy checks; csec's gateway and custom transport
refusals remain in force. No probe claims to test the real server's verdict.

The sealed privacy plugin already exists in 2.1.317 and 2.1.318; 2.1.319
factors its input helpers in `chunk-tvtpkkxr.js`. Its registration remains
default-on and trusted-settings-only. Middleware preserves downstream denies
and errors and may add an ask. Its native loader still selects the sealed
compiled module, with no environment-selected file path.

(`chunk-axsjfnwn.js:bFn` → `chunk-d9t0b6zk.js:aBn`). The Keychain

methods, separately from registry declarations. None of

The 16 new member selectors in 2.1.318 and 15 in 2.1.319 were traced to their
callers. REPL activation uses the sealed engine behind its existing feature
and administration checks. `CRYPTIC_HORIZON` adds actual events to server
safety context; prefix normalization/compression caches belong to main
requests. Feature-flag disabling uses the retirement defaults above.
`REPLY_GATE_POLICY` appears only in environment sanitization, with no active
reader. Remaining changes concern diagnostics, transcript/control timing,
remote launch metadata or packaging. They add no inspected-source exception.

Option signatures were compared in addition to whole option-shaped strings.
2.1.318's new list/output/cost flags belong to the explicit ultrareview
subcommand; `--web` and callback flags belong to MCP configuration, and
`/project --save` persists attribution metadata. 2.1.319's new literals are
downstream renderer/which/curl/git checks or hardened bundle extraction and
signature verification. Existing settings, inline code/module injection,
disabled-hook, sandbox auto-allow and bypass selectors remain guarded.

## Probes, regressions and limits

The fresh baseline passes all 64 inherited isolated cases. 2.1.318 passes
68, and 2.1.319 passes 79. The added cases exercise the material changes
above with synthetic dependencies. They import no upstream module, execute
no candidate runtime and use no real settings, identity, login, proxy or
model. They establish selected client-source behaviour, not whole-program,
native runtime, model quality, server behaviour or cryptographic correctness.
Early fixture-drift failures and their inspected corrections are retained.

Csec regressions require each exact identity to delegate and each neighbouring
hash to remain unchecked on secret, SSH and sudo. Separate synthetic admission
fixtures keep generated-policy, disk-synced-hook, relay, body/provider and CA
refusals exercised independently of the shipped catalogue. Before admission,
the complete delegation and protocol suites fail exactly six and two new
assertions respectively. After admission, all four complete affected suites
exit 0: `--claude-delegation-only`, `--delegation-protocol-only`,
`--delegation-setup-only` and `--claude-session-facts-only`. The optional live
Claude identity check is explicitly unset.

The full package build with `--jobs 2 -Xswiftc -warnings-as-errors` exits 0.
It emits the existing non-Sendable default-function diagnostic at
`SudoReviewEnd.swift:143`; this result is not a warning-free build.

The full `bin/ci` attempt exits 1 at the unchanged iPhone UI suite, after
passing Go build/vet/tests, installer and simulator orchestration fixtures,
the release watchdog, source/plist checks and unsigned Simulator/device
builds. Of its 37 UI cases, 34 pass; the missing-pairing-confirmation case
fails its inverted refresh assertion, and the iCloud-account/network and
alert-opening cases reach the existing 120-second limit. The final runner
reports host load 164/248/243 on ten CPUs. All three pass unchanged on a
fresh clone using the preserved build products and the original time limits
(three tests, exit 0). The examples belong to `csec-0.70`.

The later `bin/ci` stages did not run. Landing therefore uses the documented
[`finishing-work.md`](../agents/finishing-work.md) affected-suite fallback:
the four complete affected suites and full-package warnings-as-errors build
above. No single full CI invocation passed, and the unchanged UI recheck
does not turn the original failure into a successful full run.
